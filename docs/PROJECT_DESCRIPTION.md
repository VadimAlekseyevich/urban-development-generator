# Описание выпускной квалификационной работы

## Тема

**Разработка сервиса процедурной генерации и моделирования развития городской застройки с учётом пространственных, инфраструктурных и демографических ограничений.**

## Постановка задачи

Основной сценарий системы — **расширение существующего города**. На вход подаются границы территории, существующие дороги, здания и инфраструктура, рельеф, природные и иные ограничения, а также параметры развития территории. Система определяет пригодные для освоения области и формирует новые элементы городской структуры с учётом уже существующей застройки.

Дополнительно поддерживается **генерация городской структуры с нуля**. Оба режима используют одно алгоритмическое ядро; существующие объекты в режиме расширения считаются фиксированной частью исходной модели.

## Алгоритмический конвейер

1. анализ территории и ограничений;
2. функциональное зонирование;
3. построение или расширение дорожной сети;
4. формирование кварталов;
5. размещение застройки;
6. расчёт населения и размещение инфраструктуры;
7. проверка ограничений и оценка результата.

## Входные данные

Система работает с геопространственными и статистическими данными:

| Данные | Источники | Форматы |
| --- | --- | --- |
| Границы территории | открытые/муниципальные данные | GeoJSON, Shapefile, GeoPackage, GML |
| Рельеф | цифровые модели рельефа | GeoTIFF |
| Дороги | OpenStreetMap, открытые транспортные данные | PBF, GeoJSON, GeoPackage, Shapefile |
| Здания | OpenStreetMap, Overture Maps | PBF, GeoJSON, GeoPackage, GeoParquet |
| Инфраструктура | OSM, Overture, муниципальные данные | GeoJSON, GeoPackage, GeoParquet |
| Водные и природные объекты | OSM, открытые геоданные | GeoJSON, GeoPackage, Shapefile |
| Землепользование | открытые спутниковые/геоданные | GeoTIFF, GeoJSON, GeoPackage |
| Градостроительные ограничения | генплан, ПЗЗ, пространственные системы | GeoJSON, GML, Shapefile, GeoPackage, WMS/WFS |
| Население | WorldPop и другие источники | GeoTIFF, CSV, XLSX, GeoJSON |
| Демография | Росстат и региональная статистика | CSV, XLSX |
| Параметры генерации | пользователь | JSON, параметры интерфейса |

После загрузки данные приводятся к рабочей системе координат проекта и преобразуются во внутреннюю модель.

## Алгоритмы

### Анализ территории

Операции над геометриями, буферизация, пересечение/объединение областей, анализ рельефа и формирование карты пригодности территории.

### Функциональное зонирование

Диаграммы Вороного, итеративное расширение областей и правила, учитывающие пригодность, существующую застройку и параметры сценария.

### Дорожная сеть

Графовое представление существующих и новых дорог. Используются поиск пути, правила роста сети, Дейкстра, A*, а при необходимости минимальное остовное дерево для получения базовой связной структуры.

### Кварталы

Дорожная сеть преобразуется в полигоны. Кварталы проверяются по площади, форме, доступности и пересечению с ограничениями. Крупные полигоны разделяются дополнительно.

### Застройка

Размещение параметризованных пятен зданий в допустимых областях с учётом площади, плотности, этажности, отступов от дорог и соседних зданий, рельефа и функциональной зоны.

Внутренняя планировка зданий, помещения, квартиры, BIM и архитектурное проектирование фасадов не входят в предмет работы.

### Население

Расчёт выполняется по параметрам застройки и плотности; при наличии исходной статистики учитывается пространственное распределение населения.

### Инфраструктура

Для образования, медицины, торговли и рекреации учитываются население, вместимость, радиус/время обслуживания и доступность по дорожной сети. Цель — максимизировать долю населения, обеспеченного объектами обслуживания.

### Проверка ограничений

Используются геометрические проверки, расстояния, уклоны, связность дорожного графа и сетевой анализ доступности инфраструктуры.

### Варианты

Случайная генерация всегда использует фиксируемый `seed`, чтобы варианты были воспроизводимыми. Сценарии сравниваются по метрикам плотности, освоения территории, связности дорог, обеспеченности инфраструктурой и нарушениям ограничений.

## Пользовательский интерфейс

Центральный элемент — интерактивная двумерная карта. На ней отображаются исходные слои, ограничения, зоны, дороги, кварталы, здания, инфраструктура, промежуточные результаты и проблемные области.

Пользователь должен уметь:

- создавать проект;
- загружать исходные данные;
- включать/выключать слои;
- задавать параметры генерации;
- запускать несколько сценариев;
- отслеживать прогресс длительных расчётов;
- просматривать метрики;
- сравнивать варианты;
- экспортировать результаты.

## Технологический стек

- Python — алгоритмическое ядро;
- Shapely — геометрические операции;
- GeoPandas/Pyogrio — векторные геоданные;
- Rasterio/GDAL — растровые данные;
- NumPy/SciPy — численные расчёты и оптимизация;
- NetworkX — дорожный граф и доступность;
- PostgreSQL/PostGIS — хранение и пространственные запросы;
- pgRouting — возможное развитие серверной маршрутизации;
- SQLAlchemy/GeoAlchemy2 — слой данных;
- FastAPI — REST API;
- Redis + worker — длительные GIS-задачи;
- React + TypeScript — frontend;
- MapLibre GL JS — 2D-картография;
- GeoJSON/GeoPackage — обмен и экспорт;
- Docker Compose — воспроизводимая среда.

## Результат ВКР

Итогом должен быть не набор отдельных алгоритмов, а работающий сервис, который на реальных геоданных позволяет расширять существующую городскую структуру или формировать её с нуля, учитывать пространственные ограничения, генерировать дороги/кварталы/застройку, оценивать население, размещать инфраструктуру и сравнивать полученные сценарии по количественным показателям.
